# MomentRead 代码审查与修复记录

审查日期：2026-09-19。基线：`37d82e1edf2468f239cefb4002685412ecfec700`（`main`，产品版本 0.3.1）。本记录来自生产源码、既有测试及本次新增回归测试；使用独立副本与合成书库。

## 结论

基线 285 项测试全部通过，但未覆盖同时到达的发送请求、全局容量拒绝后的数据库状态、OpenCode 启动准备期间取消，以及运行时探测中途切换。Chrome 验收进一步暴露了阅读器卸载时的异步回调异常。本次确认并修复 5 类问题，新增 19 项测试；最终验证结果见下表。

未调整数据模型、公共 HTTP 请求格式、数据库版本或产品交互。现有书库无需迁移。

## 已修复发现

### R1 · P1 · 运行被拒绝后仍修改讨论与草稿

位置：`server/app.ts` 的消息、解析、分支及其他生成入口；`server/runs.ts` 的容量检查。

**触发与影响：**

- 两条消息同时发送时，都可能通过 HTTP 路由开头的 `busy` 检查。两条用户消息随后都写入数据库，第二个运行才被拒绝为 409。用户看见发送失败，下一次 AI 上下文却包含被拒绝的提问。
- 三个运行占满全局容量后，向第四个讨论发送消息返回 429，但用户消息已保存、草稿已清空。新解析也会在返回 429 前创建讨论并切换工作区。
- 写入用户消息后构建上下文超过长度上限，返回 `CONTEXT_LIMIT`，却不能恢复原有草稿、消息和 revision。
- 忙碌时发起小结、检索或日报，也会留下没有对应运行的背景快照。

**修复：**沿用既有的运行时互斥队列，将容量检查放在领域写入之前；消息、讨论、工作区与背景准备放在同步 SQLite 事务中，准备失败则回滚。运行本身仍在事务外启动；已接受但 CLI 失败的运行继续保存为失败记录。匹配结束后自动启动解析也通过同一队列。

**回归证据：**`tests/integration/system-concurrency.test.ts` 检查两个同时到达的请求、全局上限、解析/分支拒绝、上下文溢出，以及小结/检索/日报忙碌时的记录数量。断言数据库中的消息、草稿、revision、工作区与背景，而非只检查 HTTP 状态码。

### R2 · P2 · OpenCode 在启动准备期间忽略取消

位置：`server/ai/opencode.ts` 的 `start` / `cancel`。

**触发与影响：**调用 `start` 后立即取消。旧实现先异步查找程序、创建目录和配置，之后才把任务加入运行表；期间 `cancel` 查不到任务并直接返回，稍后仍会启动生成。该窗口也允许适配器的两个同讨论启动同时通过检查。

**修复：**首次异步操作前预留任务与讨论；取消记录在准备状态中，在 spawn 前检查。失败或取消都会释放预留；长输入临时附件在未启动进程时清理。已启动的进程继续使用原有 SIGINT / 超时强停流程。

**回归证据：**`tests/unit/opencode.test.ts` 验证立即取消只能得到 `cancelled`，不会设置实际调用成功状态；并发启动只接受一次；长输入取消后无附件残留；配置失败后再次启动不会被旧预留卡住。测试使用本地合成 CLI 子进程。

### R3 · P2 · JSON 字符串中的花括号被误当成对象边界

位置：`server/ai/opencode.ts` 的 `extractStructuredOutput`。

**触发与影响：**模型输出带 Markdown 围栏或前后文字的 JSON，小结正文含 `{` 或 `}`。旧提取器对所有花括号计数，可能提前截断或判定对象未闭合，使合法的小结无法生成。纯 JSON 的直接解析路径不受此问题影响。

**修复：**对象扫描时跟踪字符串与转义状态，字符串内的括号不改变嵌套深度；保留最终 `JSON.parse` 校验。

**回归证据：**覆盖左右花括号、转义引号、反斜杠和嵌套对象/数组。

### R4 · P2 · 运行时状态混合两个 provider 的信息

位置：`server/app.ts` 的 `runtimeInfo`。

**触发与影响：**GET `/api/runtime` 正在等待 Claude 的异步 probe 时，另一个请求切换为 OpenCode。旧实现可能返回 Claude 的版本和安装状态，同时标注 OpenCode provider/model，误导连接状态判断。

**修复：**在第一个 await 前固定 provider、adapter 和所选模型；一次响应保持同一时刻的配置归属。允许响应反映请求开始时的旧配置，不把不同运行时的数据拼在一起。

**回归证据：**用可控 probe 暂停 GET，在切换成功后释放旧 probe，验证返回的版本、provider、模型列表和所选模型一致。

### R5 · P2 · 阅读器卸载后仍访问已移除的 iframe

位置：`vendor/foliate-js/paginator.js` 的 View/Paginator 生命周期，以及 `src/reader/EpubReader.tsx` 的清理函数。

**触发与影响：**阅读器尚在加载章节、字体或等待 resize/animation 回调时离开页面。旧 Paginator 的 destroy 假定视图已存在，且对错误的目标调用 `unobserve`；Reader 为避免该异常，在首章未创建时跳过清理。迟到的布局回调可能访问已移除 iframe 的空 document，Chrome 捕获到 `Cannot read properties of null (reading 'documentElement')`。

**修复：**destroy 可重复调用、可在首章创建前调用；断开实际 observer，终止待完成的 iframe load，忽略销毁后才返回的章节、字体及布局回调。Reader 始终调用清理。补丁来源与维护约束写入 vendor 说明，上游版本不变，iframe sandbox 不变。

**回归证据：**新增 `tests/unit/reader-lifecycle.test.ts`，修复前 3 项全部失败，其中一项精确复现 Chrome 中的空 document 错误。覆盖首章前销毁、章节迟到、iframe 移除后的布局与挂起 load 清理。

浏览器脚本也修正了一个验收竞态：切换视口并重载前，通过公开的书架按钮等待保存队列排空，避免未保存状态触发 beforeunload 后中断测试。继续保留零页面异常断言，并输出异常堆栈，未屏蔽阅读器错误。

## 仍需独立验证与后续维护

- 本次没有调用真实付费模型，也没有读取真实用户 EPUB。真实 Claude/OpenCode 首次调用、接续、取消及网络搜索能力仍需在目标 provider 上单独验收。
- 自动原著发现此前在仓库文档中标记为未放行；本次没有重新验证外部服务，不据此判断其当前是否已恢复。
- 架构文档仍有“唯一 Claude 后端 / OpenCode 未进入运行路径”等旧描述，与 0.3.1 的双运行时实现不符；健康接口版本也仍写死为 0.1.0。这些属于非阻塞的文档/诊断维护项。
- 上传入口主要按声明的 Content-Length 提前拒绝过大请求，之后才解析 multipart 并执行文件格式/大小限制。后续宜增加对无 Content-Length 或分块请求的实际字节上限；本次未做超大请求压力测试。
