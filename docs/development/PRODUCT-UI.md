# 生产界面接入（F）

实现范围为 `src/product/`。保留已确认的深色、中文衬线阅读与三栏布局，使用真实书库、EPUB 阅读适配器和 HTTP／SSE 服务。首屏空书架；没有演示书、模拟 AI 文本或定时生成回复。

## 模块与数据流

- `App` 负责页面、操作与弹窗编排；使用统一 `src/api.ts`，不读取数据库或调用 CLI。
- `useWorkspace` 负责书内状态同步、草稿／阅读位置的保存队列、响应归属和运行权限事件。只在存在活动运行时以 700 ms 刷新书籍状态，SSE 的 `run` 事件用于权限与结束同步。
- `DiscussionPane` 只显示当前讨论的消息和运行。普通追问不创建节点；分支通过已完成 AI 消息的真实 DOM 选区生成 `{messageId,start,end,exact}`，重复词依靠 UTF-16 偏移区分。
- `RouteRail` 根据 `parentId` 布局。节点默认无标签；hover／focus 显示标题，仅活动节点为蓝色光圈。活动祖先路径不会被折叠遮住，切换后自动滚动定位；长路径通过完整祖先弹窗补充。
- `Library`、`Panels` 分别承载书架和导入／来源／历史／概念档案／每日成果。HTML 和备份由服务端生成，以受控下载接口取得。

## 交互约定

1. 正文选择触发 `ReaderProps.onSelection`，确认「解析一下」后创建根讨论。自动原著匹配与解析的衔接由服务端处理；界面根据全部运行状态同步阶段。
2. 在已完成 AI 回答中选择概念，再点击「展开选中的概念」。名称可编辑，真实引用偏移保持不变。再次展开即建立下一层，同一段可拥有多个兄弟。
3. 草稿与讨论滚动位置、阅读位置、字号及折叠状态去抖 500 ms 保存。切换讨论、切换书籍、进入书架／报告前等待保存完成。保存队列会继续保存正在提交期间产生的新修改；失败保留编辑并提示重试。
4. 正常关闭时对尚未完成的保存发起 `keepalive` 请求，并显示浏览器离开提示。只有服务端确认后显示「已保存」；不把离开时尽力发送当作已成功。
5. 讨论整理完成后展示可编辑草稿；确认和重试复用同一 `requestId`。409 版本冲突保留文字，可重新整理并沿用当前编辑；成功后才返回直接父讨论。根节点只保存自己的小结。
6. 原著候选展示取回、核对、版本与来源时间。选中候选仍待核对；确认已对照时同时将其选作当前依据。旧来源保留在列表，取回失败不渲染成原文引句。可补充本书的原著 EPUB／TXT。
7. 每日成果按明确日期和时区读取，生成 AI 总结是独立动作，HTML 下载来自已保存记录。备份恢复入口仅空书库可用，服务端仍作最终校验。
8. 网络权限请求显示运行所属讨论与工具输入，分别提供「允许这一次」和「拒绝」。运行中断／失败保持可见，用户可重新提问或整理。

## 尺寸与访问

- 1487 × 1058：正文、当前讨论、右侧线路图三栏。
- 1280 × 720：保留三栏并缩减边距，正文与讨论独立滚动。
- 390 × 844：正文／讨论切换；讨论旁保留可横向滚动的线路图，节点仍为 42 px 点击范围。没有缩放整个图的交互区域。
- 弹窗支持 Escape、Tab 焦点循环与关闭后焦点恢复；控件具备中文可访问名称。正文选区与 AI 消息选区由真实 DOM 产生。

## Markdown 与书籍资料追加

AI 已完成回复、流式内容、回馈／历史小结、概念定义、日报和编辑区排版预览共用 `react-markdown` + `remark-gfm`。标题、列表、强调、引用、表格、行内／围栏代码按语义渲染；长表格与代码在自己的容器内滚动。禁用 raw HTML，不自动加载模型图片，链接只允许显式安全协议。

分支选区按 Markdown AST 的原始 UTF-16 位置映射；可见词跨越强调、链接或代码边界时，`origin.exact` 保存连续原始切片（可能包括中间的 Markdown 标记），显示名称使用实际选中的可见文字。实体解码和反斜杠转义保留原始边界；半个 emoji／实体扩展、生成占位文字或不能准确映射的选区明确拒绝，不用字符串搜索猜测引用。

概念档案把来源 JSON 解析为章节、正文选段与父讨论触发词，不显示内部 ID／CFI。书名可以点击进入「书籍资料」，编辑书名、作者、译者、版本、语言和标识，保存通过统一 API；文件版本和原始引用不受影响。

新增 `product-markdown.test.tsx` 通过 11 项真实 DOM／source mapping 与安全渲染检查；连同此前 14 项共 25 项 UI 相关测试。实际浏览器外观、选择建分支和资料补录仍由总负责人复核。
