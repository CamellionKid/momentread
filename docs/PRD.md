## 1. 产品定义

一本书一个长期保留的 AI 精读空间。用户正常阅读可选中文字的中文 EPUB；遇到不懂的段落时请求 AI 寻找对应外文原著，进行翻译、拆解与举例；在 AI 解析中遇到陌生概念时打开分支，讨论后主动整理并返回。系统保存阅读进度、讨论和有出处、可修订的概念理解，并生成给用户回看的 HTML 阅读总结卡片。

核心价值：深入概念后仍能回到原来的阅读思路；后续解释能沿用已建立的概念区分，而不把同一术语固定成唯一含义。

“一本书一个空间”是用户体验要求，不表示整本书和全部历史必须放在单次模型上下文里。

## 2. 目标用户、问题与成功信号

首个用户是 Darren：以中文旧译本阅读哲学等概念密集的著作，需要借助德语、拉丁语、英语等原著辨析译文和论证。本文不预设某个术语在某本书中固定有几种含义；实际区分须以对应文本为依据。

| 当前问题 | 产品响应 | 可观察的成功信号 |
|---|---|---|
| 旧译文难懂，术语含混 | 原著匹配、建议译文、内容拆解、例子 | 用户能指出该段含义及重要译法差异 |
| 在主聊天中不断追问导致偏离 | 概念讨论进入独立分支 | 返回后无需重新讲述书籍和段落背景 |
| 独立聊天缺少上下文 | 自动继承来源段落、解析和相关书内记忆 | 分支首先解释该概念在此处的意义 |
| 同词多义被统一成一个解释 | 分语境维护概念档案 | 后续解释区分已有用法；冲突保留为待核 |
| 阅读成果难以感知 | HTML 总结展示具体理解变化 | 用户能回看今日澄清了什么、留下什么问题 |

讨论次数、阅读时长、关闭分支和确认摘要，都不等于掌握知识。

## 3. 已确认与草案建议

### 3.1 用户已确认的要求

- 以可复制文字的 EPUB 正常阅读为起点，AI 按需介入。
- 选段后可直接问“这个是什么意思，解析一下”；解析包含原文翻译、内容拆解、例子。
- 概念分支来自 AI 解析中仍不懂的概念。
- 同一选段及其解析可以展开两个或更多概念讨论；每个概念讨论中的选段也可以继续展开子概念讨论。“同一个字段”在本稿按同一段选中文本理解，不绑定表单字段。
- 默认由产品自动寻找并匹配外文原著；用户提供原著文件可作为增强途径。
- 一本书长期接续，不再要求生成给人阅读的交接文档；具体学习信息保存在产品 memory 中。
- 分支通过“整理并返回”主动收尾。
- 左侧 EPUB 阅读，右侧 AI，最右侧简洁线路图。
- 线路图为黑白灰，当前节点有蓝色光圈；默认无文字，悬停节点才显示文字。
- 已选第 3 张深色方案，保留其字体与阅读排版；线路图必须表达同级分支及多级父子关系。
- 输出 HTML 阅读总结卡片，让学习进展可见。
- 首版为本地运行、浏览器打开的网页应用，接受安装依赖和配置 AI 环境的使用门槛；不要求别人只打开公网网址就能使用。安装与使用方法必须在 README 中说明清楚。

### 3.2 本稿建议，尚非最终结构决定

- 首版以桌面浏览器尺寸设计；App 封装后置。本地服务和 AI 后端的具体实现另行选择。
- 普通追问留在当前讨论；用户主动“展开概念”时才新建节点。界面如何折叠大量节点可继续调整，但不以一级分支限制产品能力。
- “整理并返回”先产生可编辑小结，用户再确认返回；用户已确认主动收尾，二次确认的具体界面仍可调整。
- 先做单书记忆隔离；跨书关联、账户和跨设备同步后置。
- 内容引用、讨论全文和概念结论分别保存，避免仅靠摘要恢复全部历史。
- 主线相关位置可触发少量可跳过的回顾提问，不设强制答题门槛；触发频率需真实阅读验证。

## 4. 核心使用流程

1. 打开 EPUB，进入该书空间；恢复上次章节和阅读位置。
2. 正常阅读，AI 不自动讲解全文。
3. 选中不懂的段落，点击“解析一下”，可直接发送或补充问题。
4. 右侧建立一次段落解析；最右侧生成一个主线节点。
5. 系统用书籍信息、章节和选段附近文本寻找对应外文段落；展示核对状态。
6. AI 给出一句话概括、原文与译法、内容拆解和例子。
7. 用户在 AI 解析中选中不懂的概念，点击“展开概念”；右侧切换到该概念分支。同一来源可分别建立多个平级概念讨论。
8. 分支继承必要背景，用户继续追问；其中又出现不懂的概念时，可以再次展开子分支。左侧阅读位置保持不动。
9. 用户点击“整理并返回”，查看并可编辑小结，确认后保存正式回馈。
10. 右侧恢复直接父讨论及滚动位置，当前光圈回到父节点。子分支先回到概念讨论，概念讨论再整理回段落解析；不跨层自动结束父讨论。
11. 后续选段分析调用相关概念记录，必要时辨别新用法或提出可跳过的回顾问题。
12. 用户结束本次阅读时生成 HTML 总结；下次打开该书直接接续。

## 5. 功能需求

### F01 EPUB 阅读与定位 · 首版必需

- 打开可选中文字的 EPUB，提取书名、作者、译者、版本和目录；缺失信息标记未知，可补充。
- 支持连续滚动阅读、章节导航、字体大小调整和文本选取。
- 阅读位置与段落引用必须独立于当前字号、窗口宽度和屏幕页码；换字号或调整面板后仍可恢复位置。
- 每个解析绑定原书文件版本、章节、选段及上下文，不只存一个显示页码。
- 不支持或损坏的文件给出原因；首版不承诺扫描件 OCR 或受保护文件处理。

### F02 选段解析 · 首版必需

入口：在左侧选取文字后显示“解析一下”。默认问题为“这段是什么意思？请解析一下”，允许补充。

默认响应结构：

1. **这段在说什么**：先用容易理解的话概括。
2. **原文与译法**：对应原文、版本及来源、建议译文、关键译法差异；没有可靠原文则明确说明。
3. **内容拆解**：句子关系、论证步骤和必要前提。
4. **例子解释**：例子与原文的对应关系及适用边界。

区分原书内容、AI 解释与用户观点。举例或类比标记为解释材料，不伪装成作者案例。重复追问保留在同一解析讨论中，不自动扩充线路节点。

### F03 原著寻找与匹配 · 首版必需，需优先验证可行性

输入：书名、作者、译者和版本（如有）、章节标题、选段及必要的附近文本。缺失或冲突影响定位时再请求补充。

流程：识别原著及语言 → 查找可访问的文本来源 → 结合章节和上下文定位候选 → 展示匹配依据 → 对照分析。找到候选与核对通过是不同状态。

| 状态 | 用户看到什么 | 后续规则 |
|---|---|---|
| 正在寻找 | 当前正在匹配，允许继续阅读 | 不阻塞 EPUB 操作 |
| 找到可核对段落 | 外文段落、出处、版本、章节和匹配依据 | 可据此给出对照解释，保留核对记录 |
| 有多个候选 | 候选及上下文差异 | 选择前不把某一个作为已确认原文 |
| 仅找到其他版本或转译本 | 明确的语言和版本差异 | 作为参考；不冒充该旧译本的确切底本 |
| 未找到／来源不可访问 | “尚未对照原文”及可行的下一步 | 可以继续解释中文；不得编造原文和出处 |
| 用户后来补充文件 | 文件内定位结果和对旧结论的影响 | 允许重新核对，不静默覆盖原有解释 |

AI 回译、重构的外文不能展示为检索所得原文。无依据的百分比置信度不作为证据。外部检索和模型服务的具体提供方、发送范围及存储方案待实现前确定。

### F04 同源多概念与递归分支 · 首版必需

- 从 AI 回复中选中术语或短语，点击“展开概念”。
- 创建后即显示分支节点，建立到直接父讨论、父讨论中触发它的文字位置、根段落解析及原书段落的关联。
- 带入书籍信息、原书选段及原文核对状态、直接父讨论中的概念片段与问题、必要的祖先路径背景、本书相关的既有概念记录。未确认的解释仍保持暂定状态。
- 首先回答“这个概念在当前语境是什么意思”，用户再决定是否扩展。
- 分支使用右侧同一 AI 面板，不另开浏览器窗口；临时切换节点不丢失对话和草稿。
- 同一段落或同一 AI 回复片段可展开多个概念分支；它们共享来源，不共享对话状态、草稿或回馈状态。
- 每个概念分支也可以继续创建子分支；该规则递归适用，不写死“最多一级”或“最多两级”。层级很深时改变导航展示，而不是静默丢弃节点。
- 右侧仍显示一个当前活动讨论，所有分支作为独立讨论保留；不随层级不断增加横向聊天面板。
- 右侧顶部显示可导航的路径，例如“段落解析 → 概念甲 → 子概念甲一”。这是讨论面板的导航，不是在线路图上常驻文字。过长路径保留当前与直接父级，其余在省略入口中展开。
- 两个讨论即使使用相同术语也不能按名称强制合并；它们可关联同一概念档案，但保留各自来源与语境。

示例关系仅说明讨论层级，不断言概念之间的哲学分类：同一段落解析 P 下有概念甲 A 和概念乙 B；在 A 的回复中展开子概念 A1；在 A1 的回复中仍可继续展开 A1a。A 与 B 是兄弟讨论，A1 的直接父讨论是 A，而不是 P 或 B。

### F05 整理并返回 · 首版必需

建议状态流程：进行中 → 生成小结 → 待确认 → 已回馈。生成失败回到可重试状态，原讨论保留。

小结字段：

- 本次概念与当前语境中的含义。
- 核心结论、相关出处和核对状态。
- 尚未解决的问题或有争议的解释。
- 与来源段落的关系。

用户可修改或取消小结。确认成功后才将其标记为正式回馈，并返回直接父讨论原位置。保存失败时保留待确认小结，不假装完成。重新整理产生可追溯的新版本，不静默抹去历史结论。

回馈逐层进行：A1 的小结先交给 A；A 整理时结合已确认子分支中与当前问题相关的结论，再交给 P。A1 的确认不会自动完成 A、B 或 P，也不把 A1 的全文同步给全部兄弟讨论。根主线后续按相关性取用书内记录时保留来源和确认状态。

父讨论仍有进行中的子分支时，允许暂时返回。整理预览需列出未完成事项，不把它们自动标为已解决。父级之前已经回馈、子级后来新增或修订结论时，提示父级“有待合并的子分支更新”；旧的已确认回馈保留，用户重新整理后再更新父级摘要。

点击线路图离开分支只改变当前位置，不等于回馈；关闭面板不等于完成；确认小结不等于掌握。

### F06 黑白线路图 · 首版必需

- 位置：AI 面板右侧的窄栏；主线为纵向排列。同一主节点可以向侧面分出两个或更多概念节点，概念节点又可继续分出子节点。连线必须明确指向直接父节点，不能把子孙都画成根节点的平级分支。
- 主线节点代表一次选段解析，分支节点代表一场概念讨论；不是自动生成的全书目录。
- 默认只有灰黑或灰白线条、圆形节点，无常驻标题、编号、图例或彩色分支。
- 全图仅当前节点有一个静态、轻微的蓝色光圈。蓝色表示位置，不表示正确、掌握或完成。
- 任意节点悬停时显示简短名称；移出后隐藏。键盘聚焦也可读取同等信息。
- 点击切换右侧讨论并恢复该讨论的位置，同步右侧路径导航；左侧不自动跳走，可经明确的“定位原文”动作查看来源。允许直接点选任意祖先、兄弟或后代节点，这只是导航，不触发整理或跨层回馈。
- 节点视觉可以很小，但点击命中范围应更宽；文字浮层避免遮挡待点击节点。
- 节点多时窄栏独立滚动，当前节点可见；当前祖先路径保持展开，不占用整屏成为自由拖拽画布。非当前子树可以折叠，折叠状态使用灰色叠圈等非文字标记，并能悬停查看、展开；折叠不删除讨论。
- 当前路径超过窄栏可容纳深度时，提供局部展开或横向浏览来查看后代；右侧面板始终保留路径入口。可视宽度限制不等于数据或功能层级限制，具体手势待可点击原型验证。
- 分支进行中、已回馈等状态可在悬停文字内提示，不新增颜色体系。

### F07 单书学习记忆与恢复 · 首版必需

这里的 memory 是未来产品的书内学习数据，不是本机 Agent 全局记忆，也不代表本次已经修改任何全局 memory。

| 信息类别 | 需要保留的内容 | 约束 |
|---|---|---|
| 阅读状态 | 当前章节、原书位置、活动节点、讨论滚动位置、待续事项 | 原书换版本时不能直接沿用旧定位 |
| 来源与讨论记录 | 原书引用、外文匹配依据、AI 回复、用户追问、直接父讨论、根解析、触发文字位置与祖先路径 | 原文、AI 判断和用户观点可辨别；同源兄弟讨论独立 |
| 概念档案 | 原文术语、中文译名、不同用法、适用段落、出处、待解争议 | 不按中文词面强制合并全部含义 |
| 正式回馈 | 用户确认的小结、修订记录、直接父讨论、所引用子分支小结及其版本 | 与未确认讨论分开；子级更新不静默改写父级已确认结论 |
| 理解证据 | 用户自己的表述、回答、容易混淆的点 | 无回答证据不标成已掌握 |

后续分析按当前段落取用相关记录；若与既有解释冲突，指出差异并提出待核问题。旧解释可修订，但保留其原来适用的语境。学习目标可选填，不作为打开书籍的必填表单。

部署方式已确定为本地网页版。建议产品学习记录优先在本机保存；具体目录、数据库及备份方式尚未定案，跨设备同步后置。本地运行不代表远程模型和检索服务不会接收请求内容，README 必须说明实际数据流向。

### F08 渐进回顾 · 首版保留轻量版本，策略待验证

- 后续段落关联到已讨论概念或未解决问题时，可以结合旧结论解释，或给出一道简短、可跳过的问题。
- 不因为用户刚回到主线就强制考试；不打断正常阅读，不锁定继续按钮。
- 依据实际回答更新理解记录，保留不确定性；具体触发频率、是否默认开启需要阅读试用决定。

### F09 HTML 阅读总结 · 首版必需

用户主动生成本次／今日阅读卡片，内容可在浏览器打开，也可保存为 HTML。

- 看了哪本书，今天从哪里读到哪里，当前停在哪里。
- 讨论了哪些概念，哪些形成了确认小结，哪些仍待解决。
- 今天澄清了什么译法、区分了什么用法、哪个理解发生了改变。
- 一段今日总结与一到两条具体建议，下一次从哪里继续。
- 用真实阅读记录区分“已讨论”“已确认小结”“有回答证据的理解”，不生成虚假的掌握率或成就。

卡片用于人类回看和感知进展；无需夹带给新 AI 的交接提示词。产品内可继续到原讨论；独立导出的 HTML 即使脱离应用，也应能读懂内容和来源说明。

## 6. 界面与视觉约束

核心屏幕为桌面三栏：左侧 EPUB、右侧 AI、最右侧窄线路图。EPUB 文字是阅读主体；自动找到的外文原著放在 AI 解析中按需展开对照，不再增加第四个固定阅读栏。

共同约束：黑白灰、克制留白、清晰文字层级；蓝色仅作为线路当前位置的强调；不将每段文字包装成卡片。左、右区域独立滚动。

用户已选择初始第 3 张的深色与字体。后续修订保留其视觉基础；线路图明确展示“同一来源的两个概念分支”和“分支下的子分支”，蓝色光圈落在实际活动的子节点，右侧路径导航与之对应。只对承载层级所必要的空间作调整。

示意图使用标明为演示的内容，不作为已核对原著或真实学习成果。用户已认可多级分支修订图；后续可点击原型以该图为视觉目标。

### 6.1 载体与安装体验 · 已确认

- 用户按 README 安装依赖并配置所选 AI 后端，启动本地服务，再用桌面浏览器打开阅读工作台。
- 首版不要求公网托管、多租户账户、零安装访问或桌面 App 安装包。
- README 必须区分产品服务和 AI 运行服务，说明是否需要分别启动、如何确认连接成功，以及如何停止和重新启动。
- 可接受合理的环境配置门槛，但启动失败须给出可操作的提示；不能要求用户猜端口、数据目录或凭据配置位置。
- 正式交付时，README 中的依赖版本、安装命令、启动命令、配置示例和首次阅读流程必须在干净环境中验证。
- 当前的 [README](../README.md) 是文档阶段草稿；本项目还没有可执行应用，不将候选工具的启动命令冒充本产品入口。

### 6.2 AI 接入责任边界 · 方案建议，待确定首个后端

推荐复用现成 harness，产品保留最小的学习状态管理。载体选择不等于已选定 OpenCode、Claude Code 或 DeepSeek Harness。

| 现成运行环境可承担 | 阅读产品必须承担 |
|---|---|
| 模型调用、工具执行循环、会话恢复、运行时上下文处理 | EPUB 选段、节点与会话关联、直接父子关系、当前位置 |
| 接收上下文并生成分支解释和小结 | 传入哪段书籍背景、用户是否确认、回馈到哪个父讨论 |
| 使用已提供的文件、记录和工具 | 维护概念用法、出处、核对状态与修订；不以自动压缩替代概念档案 |

候选：

- [OpenCode Server](https://opencode.ai/docs/server/)：现成 HTTP 服务提供会话、fork、消息和事件流；此前建议优先验证网页对接，现结合 ThoughtDAG 的现成桥接重新比较验证顺序，后端尚未定案。
- [Claude Code 程序化调用](https://code.claude.com/docs/en/headless)：可通过非交互 CLI、流式输出和会话恢复接入，需要本地桥接。
- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：提供本地 Web UI 和插件式 harness，可评估以插件扩展阅读能力；上游目前标为开发者预览。

以上完成了官方资料和本机 CLI 版本／帮助检查，尚未对本产品进行端到端接入验证。直接模型 API 和外部 chatbot 网页仍是比较过的替代方向，未作为首版已确认实现。

## 7. 首版范围与暂不纳入

首版闭环：EPUB 导入与定位 → 自动原著匹配或明确降级 → 选段解析 → 多个同级概念与递归子分支 → 整理、确认并逐层返回 → 单书记忆与恢复 → HTML 阅读总结。

暂不纳入：跨书知识图谱、社交分享平台、多人协作、自动全文重译、OCR、多端账户同步、完整间隔复习系统。除用户已明确取消的人工交接文档外，这些是范围建议，可在后续调整。递归分支已纳入首版；不承诺无限数量节点的性能，实际规模需运行验证。

## 8. 验收场景

以下是待实现后的验收条件，不是已经通过的测试。

| 编号 | 操作与条件 | 预期结果 |
|---|---|---|
| A01 | 导入可选文字 EPUB，修改字号并重新打开 | 章节、阅读位置仍能恢复；不依赖旧屏幕页码 |
| A02 | 从书中选段请求解析 | 右侧出现对应讨论，绑定正确书籍和选段，线路出现一个主节点 |
| A03 | 选取 AI 解析中的概念创建分支 | 分支知道来源段落，左侧不跳动，当前蓝圈转到分支 |
| A04 | 悬停和点击不同节点 | 默认无标签；悬停可识别；全图只有当前节点蓝圈 |
| A05 | 分支讨论中临时切换到其他节点再回来 | 对话和草稿仍在，不被标记为已回馈 |
| A06 | 整理小结后修改并确认返回 | 修改后内容保存；恢复直接父讨论滚动位置；可追溯原讨论 |
| A07 | 整理生成或保存失败 | 可重试且不丢讨论，不显示虚假的完成状态 |
| A08 | 无法找到原文／有两个相似候选 | 保留核对状态；继续中文解释或选择候选；不编造引文 |
| A09 | 后文同一术语出现不同用法 | 结合当地语境，保留多义或待核冲突，不强套单一定义 |
| A10 | 补充新原著版本并重新核对 | 提示受影响的解释，历史来源与修订可追溯 |
| A11 | 关闭书籍空间再打开 | 阅读、活动讨论和确认小结接续，无需人工交接文档 |
| A12 | 导出今日 HTML | 书籍、进度、概念和待解问题与记录一致；离线可阅读文本 |
| A13 | 后续遇到已讨论概念并跳过回顾问题 | 继续阅读不受阻，跳过不被解释为答错或掌握 |
| A14 | 从同一选段／回复分别展开概念甲和概念乙 | 两个兄弟节点均指向相同来源；切换不混合对话或草稿 |
| A15 | 在概念甲中展开甲一，再从甲一展开更深分支 | 每级父子关系、根段落、上下文和路径正确；不被降级为平级节点 |
| A16 | 在甲一中“整理并返回” | 回馈只交给直接父讨论甲；光圈和面板回到甲，不跳到根解析 |
| A17 | 在兄弟节点间切换并重开书籍 | 恢复独立讨论及活动深层节点，其他节点不被自动完成 |
| A18 | 父级已回馈后修订子级小结 | 父级提示待合并更新，旧回馈保持原样，可重新整理 |
| A19 | 当前路径很深，折叠和展开其他子树 | 当前节点与路径可定位；能找回折叠节点，没有数据丢失 |
| A20 | 新用户仅依照正式 README 配置并启动 | 可打开本地网页，辨认 AI 连接状态，完成一次选段解析与子分支返回；安装命令有干净环境验证记录 |
| A21 | AI 服务未启动或不可用时打开产品 | 可以识别原因，已有阅读内容和记录仍可访问；重连不丢失当前分支 |

试用应记录能否顺利返回、用户为恢复背景重复说明了多少内容、原著候选匹配对错、概念用法是否被混淆。先建立真实阅读基线，再确定数值目标。静态图、代码检查和模拟数据不能证明学习效果。

## 9. GitHub 开源复用调研

核查日期：2026-09-10。以下结论来自上游 README、许可文件和少量示例代码的只读核查；尚未安装、集成或使用真实 EPUB 运行测试。许可证名称是上游标示，不构成对未来分发方式的完整评估。

| 项目 | 可复用范围 | 上游许可 | 适配判断与限制 |
|---|---|---|---|
| [foliate-js](https://github.com/johnfactotum/foliate-js) | 浏览器电子书渲染、CFI 定位、搜索、批注覆盖层、阅读进度 | MIT | 适合优先验证的阅读内核；官方说明库 API 尚不稳定，应固定版本并隔离适配层；示例阅读器不是完整产品 |
| [epub.js](https://github.com/futurepress/epub.js) | EPUB 渲染、选区、高亮、CFI 引用及回跳 | BSD-2-Clause，见[许可](https://github.com/futurepress/epub.js/blob/master/license) | 适合作为对比候选；官方高亮示例直接覆盖本产品“选段—保存引用—回到原文”的关键动作 |
| [Readest](https://github.com/readest/readest) | 完整阅读应用；滚动阅读、高亮、翻译、双书对照等现成功能 | AGPL-3.0，上游注明可选择后续版本 | 可参考完整交互或评估整仓二次开发；应用范围明显大于本次 MVP，不能把其全部代码等同于 MIT 组件 |
| [React Flow / xyflow](https://github.com/xyflow/xyflow) | 节点关系、点击事件、自定义节点及连线 | MIT | 可制作无文字圆点、唯一蓝圈和悬停标题；对于极简只读线路图可能偏重，是否采用待原型验证 |

### 已核查的具体复用入口

- foliate-js 的 [README](https://github.com/johnfactotum/foliate-js/blob/main/README.md) 描述 `view.js` 入口、`relocate`、`goTo()`，以及 `overlayer.js`、`progress.js`、`search.js` 模块。原文定位和渲染可利用这些能力；选区提取仍需验证具体接入。
- epub.js 的 [highlights.html](https://github.com/futurepress/epub.js/blob/master/examples/highlights.html) 示例包含 `rendition.on('selected', ...)`、`annotations.highlight(...)`、`book.getRange(...)` 和 `rendition.display(...)`。
- Readest 的 [.gitmodules](https://github.com/readest/readest/blob/main/.gitmodules) 指向 `readest/foliate-js` 分支仓库。因此，研究 Readest 时还要区分它使用的 fork 和 foliate-js 上游。
- React Flow 官方的 [Custom Nodes](https://reactflow.dev/learn/customization/custom-nodes) 支持自定义节点内容与交互；本产品需要隐藏默认文本和编辑器式控件，另行实现简洁路线布局。

### 暂定建议

优先验证“阅读内核复用 + 本产品自己的学习流程”。第一候选 foliate-js，epub.js 作为同场对照；Readest 保留为完整应用改造的备选。线路图是否使用 React Flow，待布局选定后按节点规模判断。以上是建议，不是已批准的技术架构。

本轮查看的项目，没有证据证明可直接覆盖“中文选段自动对应原著 + 概念分支确认回馈 + 同词多义书内记忆”的完整闭环。这些是本产品需要新增的能力，不能把内置翻译等同于原著匹配。

进入实现后的第一轮验证，应使用用户选定的真实 EPUB：测试跨段选取、连续滚动、改变字号后定位恢复、解析与分支回跳。另取一组可人工核对的中外文段落测试匹配，覆盖无结果和歧义情形，再决定阅读内核与检索方案。
